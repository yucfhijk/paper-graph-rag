# paper-graph-rag

面向「图结构 × 大语言模型」交叉方向的学术文献检索与评测。

用一个自建的 382 篇论文语料库，实测回答一个问题：**图结构在检索里到底解决了什么，又解决不了什么。**

## 核心结论

在同一套 75 题的评估集上，让**每个检索器跑全部三类题**，得到的对照矩阵：

| 检索器 | 查询类型 | 题数 | HR@1 | HR@5 | MRR@10 | Recall@10 |
|---|---|---|---|---|---|---|
| TF-IDF | 关键词型 | 30 | 0.967 | **1.000** | 0.978 | 1.000 |
| TF-IDF | 语义型 | 20 | 0.150 | **0.350** | 0.247 | 0.450 |
| TF-IDF | 引用型 | 25 | 0.000 | 0.360 | 0.139 | 0.161 |
| 图检索 | 引用型 | 25 | **1.000** | **1.000** | **1.000** | 0.968 |

三条结论，每条都有数字支撑：

1. **关键词明确时，词法检索已经够用** —— HR@5 打满 1.000，上向量检索收益有限。
2. **换成自然语言表述，词法检索立刻崩掉** —— 同样的语料，HR@5 从 1.000 掉到 0.350。因为查询是人话改写，与论文原文没有词汇重叠，TF-IDF 匹配不到。这是语义检索的用武之地。
3. **关系型问题词法检索完全无能为力** —— 「哪些论文引用了 X」这类查询，TF-IDF 的 MRR@10 只有 0.139，图检索是 1.000。这不是程度差异，是能力有无的差异：向量检索同样答不了，因为答案不在任何单篇文档的文本里，而在文档之间的边上。

第 3 条是建图的直接理由。

## 数据

语料来自 [OpenAlex](https://openalex.org)（开放学术图谱 API，无需密钥）。

- 检索 5 组主题词，命中后按 OpenAlex ID 去重
- 三道质量过滤：类型筛选、主题词硬过滤（必须命中图类词，且除 text-attributed graph 组外必须命中 LLM 类词）、标题-摘要一致性检查
- 标题归并：同一篇论文的多来源记录（预印本版 / 正式版）合并，引用边取并集

| 项 | 数值 |
|---|---|
| 论文数 | 382 |
| 年份范围 | 2022 – 2026 |
| 原始命中 | 2000+，过滤丢弃 562 篇 |
| 标题归并 | 396 → 382（14 组重复记录） |
| 库内引用边 | 191 条 |
| 有库内出度的论文 | 89 篇 |

> 为什么不用 arXiv：共享出口常被限流（实测 HTTP 429）。OpenAlex 更稳，且 `referenced_works` 字段直接给出引用关系，是建图的现成边。

### 踩过的数据坑

- **`search` 参数太宽松**：命中 61947 篇，混入 AlphaFold 3、临床问答等无关论文。改用 `title_and_abstract.search` 后降到 4597 篇，精度大幅提升。
- **OpenAlex 存在记录错误合并**：`W4385245566` 标题是 "Exploiting Generative AI to Scale up Intelligent Tutoring Systems"，摘要却是 Mizar 定理证明，被引数虚高到 78459。用「标题关键词在摘要中的命中率 ≥ 25%」把这类脏数据剔掉。
- **同一论文的多来源记录**：14 组重复。旧记录（预印本版）的 `referenced_works` 是空的，引用边全挂在正式版上。不归并的话，实体链接会指向错误的记录，引用查询直接返回空 —— 修复前 HR@5 只有 0.840，修复后 1.000。

## 方法

### 三类查询

评估集 75 题，分三类，各自考察不同的检索能力：

| 类型 | 题数 | 构造方式 | gold |
|---|---|---|---|
| 关键词型 | 30 | 标题去停用词后的关键词 | 该论文 |
| 语义型 | 20 | 人工改写的自然语言描述，**刻意避开标题用词** | 该论文 |
| 引用型 | 25 | 「哪些论文引用了 X」 | 库内引用 X 的论文集合（平均 4.9 篇，最多 34 篇） |

语义题的关键在于改写：如果直接用标题，就退化成了关键词匹配，测不出语义检索的价值。20 条查询全部用不同措辞描述同一篇论文（例如把 "Mole-BERT: Rethinking Pre-training Graph Neural Networks for Molecules" 写成 "revisiting how self-supervised objectives should be designed for message-passing networks over chemical structures"）。

### 两个检索器

统一 `search(query, k) -> [doc_id]` 接口，便于在同一评估集上横向对比。

- **TfidfRetriever** —— TF-IDF（sublinear tf + 1-2 gram + 停用词）余弦相似度，稀疏矩阵点积排序。
- **GraphRetriever** —— 从查询中解析出论文标题做实体链接（标题归一化后精确匹配），再沿引用图的入边展开，按被引量排序。内容型查询它返回空，这正是对照组要展示的。

### 评估指标

- `HR@k` —— top-k 内是否命中任一 gold
- `MRR@10` —— 首个命中位置倒数排名的均值
- `Recall@10` —— top-10 覆盖的 gold 比例（引用型题目的 gold 是集合，只有这个指标有意义）

## 快速开始

```bash
pip install -r requirements.txt

python src/01_fetch.py       # 抓取语料（约 1 分钟，需要联网）
python src/02_eval_set.py    # 构造评估集
python src/evaluate.py       # 跑评测，输出对比矩阵
```

`data/raw/works_raw.json` 已随仓库提交，跳过第 1 步也能直接跑第 2、3 步复现全部指标。

## 已知局限

- **尚无生成层**。当前实现到检索为止，是一个 GraphRAG 系统的检索与评测模块；LLM 生成尚未接入。
- **引用图偏稀疏**。库内引用边 191 条、89 篇有出度，因为语料只覆盖近四年。引用之外的关系（共概念、共作者）尚未建边。
- **引用型题目的 Recall@10 只有 0.968**，因为 gold 最多 34 篇而 top-10 截断。这是指标定义的取舍，不是检索错误。
- **语义题的 gold 是单篇**，因此只测「能否排到前列」，不测召回完整度。
